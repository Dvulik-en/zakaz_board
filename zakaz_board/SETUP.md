# Развёртывание доски статусов — пошагово (новая версия, 4 вкладки)

## 1. Google Таблица — три листа вместо одного

Создайте Google Таблицу (например, «Заготовка - статус») и в ней три листа
(вкладки снизу в самой таблице) с именами и заголовками ровно как ниже:

**Лист `parts_pool`** (первая строка):
```
id | order | product | uzel | grade | thickness | custom_sheet | code | name | size | qty_total | area
```

**Лист `raskroi`**:
```
id | name | grade | thickness | custom_sheet | status | pdf_name | created
```

**Лист `raskroi_items`**:
```
raskroy_id | part_id | qty
```

Руками эти листы заполнять не нужно — их наполняют скрипты и сам сайт.

## 2. Доступ к таблице (сервисный аккаунт Google)

1. https://console.cloud.google.com → новый проект → включить **Google Sheets API** и **Google Drive API**.
2. IAM & Admin → Service Accounts → Create Service Account.
3. Keys → Add Key → Create new key → JSON — скачается файл, это ваш ключ.
4. Скопируйте email сервисного аккаунта (вида `...@...iam.gserviceaccount.com`).
5. В самой Google Таблице → «Настройки доступа» → добавьте этот email как **Редактор**.

## 3. Битрикс24 — вебхук для уведомлений

Портал: `https://boiler.bitrix24.by`

1. Настройки → Разработчикам → Другое → Входящий вебхук (нужны права администратора портала).
2. Права — минимум **im** (Мессенджер и чаты).
3. Получите ссылку вида `https://boiler.bitrix24.by/rest/1/xxxxxxxxxxxxxxxxxxxx/` — это `BITRIX_WEBHOOK_URL`.
4. ID нужных сотрудников — в адресной строке их профиля (`.../user/23/` → `23`). Через запятую — `BITRIX_USER_IDS`.

## 4. Публикация на Render (бесплатно)

1. Регистрация на https://render.com.
2. Загрузите все файлы (`app.py`, `sheet_store.py`, `zakaz_report.py`, `upload_parts.py`,
   `ajan_pdf_parser.py`, `requirements.txt`, `Procfile`, всю папку `templates/`) на GitHub
   одним репозиторием (через браузер, кнопка «Add file → Upload files», без командной строки).
3. Render: New → Web Service → подключить репозиторий.
4. Build Command: `pip install -r requirements.txt`
5. Start Command: `gunicorn app:app`
6. Environment → добавить переменные:
   - `GOOGLE_CREDENTIALS_JSON` — содержимое json-ключа целиком
   - `GOOGLE_SHEET_NAME` — точное имя таблицы
   - `BITRIX_WEBHOOK_URL`, `BITRIX_USER_IDS` — из шага 3
7. Deploy → получите адрес вида `https://ваш-проект.onrender.com`.

Бесплатный тариф засыпает после 15 минут простоя — первое открытие после паузы займёт 30-50 секунд.

## 5. Заливка деталей (без плана ПДО)

На рабочем ПК:
```
pip install gspread google-auth openpyxl pdfplumber
set GOOGLE_CREDENTIALS_JSON=<содержимое json одной строкой>
set GOOGLE_SHEET_NAME=Заготовка - статус
python upload_parts.py "путь к папке заказа"
```
Разбивает на уровне отдельного экселя (узла) — план ПДО открывать не нужно,
план можно держать под рукой просто как справочник, что делать в первую очередь.
Повторный запуск на той же папке не дублирует уже залитые детали.

## 6. Как это используется по вкладкам

- **ПДО** — обзор: заказ → изделие → сколько нужно / назначено в раскрои / вырезано.
- **Технолог** — создаёт раскрой (название УП, марка, толщина), фильтрует пул деталей
  по заказу/изделию/узлу или текстовому поиску, отмечает нужные детали и добавляет
  в активный раскрой с количеством. Можно прикрепить PDF от AJAN к раскрою (для истории).
- **Учётчик** — видит все раскрои в статусе «Создан», сгруппированные по марке+толщине —
  это и есть список «сколько листов выписать со склада». Кнопка «Выдано» переводит
  раскрой в очередь на резку.
- **Плазменщик** — видит выданные раскрои, одна кнопка «Вырезано» закрывает раскрой
  целиком — все детали внутри считаются вырезанными автоматически, без путаницы
  между одинаковыми деталями из разных изделий (состав раскроя зафиксирован технологом
  заранее, а не угадывается по PDF).

Уведомление в Битрикс24 уходит, когда после закрытия раскроя изделие оказывается
полностью вырезанным целиком (все его детали набрали нужное количество).

## Про DXF с сетевого диска

Пока доступа нет — ничего делать не нужно. Как только дадут доступ: складывайте
актуальные DXF в одну папку, и на следующем шаге подключим сопоставление по коду
детали — тем же принципом нормализации кириллицы/латиницы, что уже сделан для PDF.
